# Команда и роли

**Организация → Команда** — здесь вы управляете тем, у кого есть доступ к CRM и что им разрешено делать. Владелец организации может открыть её всегда — и может делегировать её участнику, выдав в роли право **Команда** (см. ниже).

## Участники

Вкладка **Участники** показывает всех в команде — имя, email и сводку доступа по проектам.

- **Добавить участника** — открывает многоразовую ссылку-приглашение для организации. Поделитесь ей; кто откроет — присоединится как участник. Ссылку можно в любой момент сбросить, чтобы старая перестала работать.
- **Управление доступом** (меню ⋮ у участника) — назначьте участнику **роль** в каждом проекте отдельно. Один человек может быть менеджером в одном магазине и не иметь доступа к другому.
- **Удалить** — отзывает доступ участника ко всей организации.

У владельца всегда полный доступ, и его нельзя удалить.

> **Команда «только просмотр».** Если ваша роль даёт **Команду** на уровне *View* (а не *Manage*), вы можете просматривать участников и роли, но кнопки действий — *Добавить участника*, *Новая роль* и меню ⋮ в строках — скрыты. Роль при этом можно открыть и посмотреть её права в режиме чтения.

## Роли

Вкладка **Роли** — где вы определяете, что роль может делать. Роль — это **матрица прав** по страницам консоли, с тремя уровнями для каждой:

| Уровень | Значение |
|---------|----------|
| **None** | страница скрыта |
| **View** | можно открыть и читать |
| **Manage** | можно редактировать / выполнять действия |

- Готовые роли уже есть (Admin, Manager, Staff, Viewer); свои создаются кнопкой **Новая роль**.
- Редактор группирует страницы и имеет массовые кнопки *Снять всё / Всё View / Всё Manage*.
- Изменения сохраняются автоматически — кнопки «Сохранить» нет.

### Что может охватывать роль

Роль покрывает два вида страниц:

- **Страницы организации** — консоль уровня организации: **Аналитика орг., Клиенты (все проекты), Команда, Платежи, Использование, Настройки орг.** Выдайте их, чтобы делегировать администрирование организации, не передавая владение. Например, участник с *Команда: Manage* может вести страницу команды за вас.
- **Страницы проекта** — всё внутри консоли одного проекта (Обзор, Товары, Заказы, Бронирование, Чат, Авторизация…), назначаются по проектам в **Управлении доступом**.

Две страницы намеренно вне матрицы:

- **Проекты** (список проектов) всегда доступны каждому участнику — их нельзя отключить.
- **Биллинг** **нельзя** делегировать никогда — открыть его может только владелец, так задумано.

## Как работает доступ

Доступ проверяется на бэкенде, а не просто прячется в интерфейсе. Участник видит только те страницы, которые даёт его роль — страницы проекта по проектам, страницы организации по всей организации — и уведомления подчиняются тому же правилу: вы не получите оповещения по проекту (или странице вроде Чата), к которым у вас нет доступа.
