# Платежи

Решите, как клиенты будут вам платить. **Torta не касается денег** — они идут напрямую на *ваш* счёт в платёжной системе (Stripe, Kaspi, Halyk, TipTop Pay, Robokassa, PayPal), либо вы собираете их сами вне платформы (Manual). Это освобождает вас от PCI-комплаенса и лицензий на работу с деньгами. Задача Torta — **проверить, записать и сверить** каждый заказ.

## Методы работают вместе

Вы не выбираете один провайдер — вы **подключаете нужные шлюзы**, а клиент выбирает один при оформлении (та же модель, что у Shopify и WooCommerce). Stripe + Kaspi + Robokassa могут работать одновременно.

| Метод | Что это | Валюты | Как ложится заказ |
|---|---|---|---|
| **Stripe** | Международная оплата картой, инлайн на вашей витрине | Большинство валют | **Оплачен** — проверяется автоматически |
| **ApiPay (Kaspi)** | Клиент вводит телефон, оплата приходит пушем в его Kaspi-приложение | **Только KZT** | **Оплачен** — проверяется автоматически |
| **ePay (Halyk)** · *Beta* | Оплата картой на хостируемой странице Halyk Bank | **Только KZT** | **Оплачен** — проверяется автоматически |
| **TipTop Pay** *(ex-CloudPayments)* · *Beta* | Оплата картой во всплывающем виджете, клиент остаётся на вашей странице | **KZT, RUB** | **Оплачен** — проверяется автоматически |
| **Robokassa** | Оплата картой на хостируемой странице Robokassa | **Только KZT** | **Оплачен** — проверяется автоматически |
| **PayPal** | Редирект в PayPal; мы списываем деньги при возврате | **Не KZT** (USD / EUR / …) | **Оплачен** — проверяется автоматически |
| **Manual** | Наличные / перевод / оплата при получении — собираете сами | Любые | **Учтён** (`manual`) |

> Каждый **онлайн**-шлюз перепроверяется на сервере, прежде чем заказ засчитается в выручку. Нажимать «Mark as paid» для них не нужно — это происходит само.

## Как подключить шлюз

Откройте **Организация → Payments**. Каждый шлюз — это строка. Шаги одинаковы для всех:

1. **Кликните строку**, чтобы открыть панель.
2. **Вставьте креды.** В каждой панели есть ссылка **Open Console** прямо на страницу в кабинете провайдера, где лежат ключи.
3. Нажмите **Save**.
4. Нажмите **Test connection**. При успехе бейдж станет **Connected**.
5. Включите переключатель **Active** — шлюз появится при оформлении заказа.

### Бейдж статуса

| Бейдж | Что значит |
|---|---|
| **Not connected** | Креды ещё не сохранены. |
| **Configured · awaiting check** | Креды сохранены, но **Test connection** ни разу не прошёл. |
| **Connected** | Проверка связи прошла. Переключатель **Active** разблокирован. |

Manual — офлайн-метод, поэтому у него просто **Enabled** / **Off**.

### Два переключателя

- **Active** — показывать ли шлюз клиенту при оформлении. Заблокирован, пока бейдж не станет *Connected*. Выключение ставит шлюз на паузу; ключи остаются сохранёнными.
- **Test mode** — применяется при нажатии **Save**. В тестовом режиме реальные деньги не двигаются, используйте тестовые карты провайдера. Выключите, когда будете готовы принимать настоящие платежи.

### Beta-шлюзы

У **ePay (Halyk)** и **TipTop Pay** есть плашка **Beta**. Они полностью реализованы и покрыты юнит-тестами, но ещё не проверены end-to-end реальными деньгами — протестируйте небольшим настоящим платежом, прежде чем полагаться на них. В каждой Beta-панели есть кнопка **Report an issue** — она пишет нам напрямую.

## Stripe

**Рекомендуем Stripe Connect** — нажмите **Connect with Stripe →** вместо вставки ключей. Это безопаснее, и вы в любой момент можете отозвать доступ Torta из своего кабинета Stripe.

Если предпочитаете ключи, откройте [Stripe → Developers → API keys](https://dashboard.stripe.com/apikeys):

| Поле | Обязательное | Выглядит как |
|---|---|---|
| Publishable key | ✅ | `pk_test_…` / `pk_live_…` |
| Secret key | ✅ | `sk_test_…` / `sk_live_…` |
| Webhook signing secret | нет | `whsec_…` |

При оформлении карта собирается **инлайн** (Stripe Elements) и идёт браузер → Stripe напрямую; она не доходит до серверов Torta. Заказ создаётся только после того, как Stripe подтвердит оплату.

> **Тестовая карта:** `4242 4242 4242 4242`, любая будущая дата, любой CVC. В test mode реальные деньги не двигаются.

## ApiPay (Kaspi) — только KZT

Оплата Kaspi идёт через **ApiPay**. Клиент вводит номер телефона при оформлении, ApiPay отправляет списание пушем в его **приложение Kaspi**, он подтверждает там, а Torta проверяет платёж на сервере.

| Поле | Обязательное | Где взять |
|---|---|---|
| ApiPay API Key | ✅ | [apipay.kz](https://apipay.kz) → **API Keys** (уходит заголовком `X-API-Key`) |
| Webhook Secret | нет | Выдаётся при создании вебхука (ниже) |

Две вещи нужно сделать в кабинете ApiPay:

1. **Подключите Kaspi-кассу** — *Settings → Kaspi Authorization*. Без этого списания не дойдут до Kaspi.
2. **Добавьте вебхук** — панель Torta показывает **Webhook URL · POST**. Скопируйте его в *Settings → Connection → Webhooks*. При создании вебхука вы получите **Webhook Secret** — вставьте его обратно в Torta.

Суммы проводятся **в целых тенге**.

## ePay (Halyk) — Beta · только KZT

Клиент платит на **хостируемой странице Halyk Bank**, затем возвращается в магазин. Torta подтверждает списание серверной проверкой статуса.

| Поле | Обязательное |
|---|---|
| Client ID | ✅ |
| Client secret | ✅ |
| Terminal ID | ✅ |

Возьмите их в [кабинете Halyk ePay](https://epayment.kz).

## TipTop Pay (ex-CloudPayments) — Beta · KZT / RUB

Клиент платит во **всплывающем виджете** и не покидает вашу страницу. Torta подтверждает списание на сервере.

| Поле | Обязательное |
|---|---|
| Public ID | ✅ |
| API secret | ✅ |

Возьмите их в кабинете [merchant.tiptoppay.kz](https://merchant.tiptoppay.kz).

## Robokassa — только KZT

Клиент платит на **хостируемой странице Robokassa**. Torta проверяет результат запросом статуса OpState.

| Поле | Обязательное | Примечание |
|---|---|---|
| Merchant login | ✅ | |
| Password #1 | ✅ | |
| Password #2 | ✅ | |
| Hash algorithm | нет | по умолчанию `md5` (`md5` / `sha256` / `sha512`) |

Возьмите их на [partner.robokassa.kz](https://partner.robokassa.kz).

**Затем вставьте URL-ы Torta обратно в кабинет Robokassa.** Панель печатает их за вас (с выбором магазина, если в организации несколько проектов):

| URL | Назначение |
|---|---|
| **Result URL · POST** | **Обязательный.** Robokassa POST-ит сюда результат оплаты. |
| **Success URL** | Куда клиент возвращается после оплаты. |
| **Fail URL** | Куда клиент возвращается при неудаче. |
| **Homepage URL** | Главная страница магазина. |

> Ссылки Success / Fail строятся из URL сайта вашего магазина. Если они пустые — сначала задайте его в **Authentication → URL configuration**.

## PayPal — не KZT

Клиент редиректится в PayPal, подтверждает платёж, а Torta затем **списывает и подтверждает его на сервере** при возврате.

| Поле | Обязательное |
|---|---|
| Client ID | ✅ |
| Client secret | ✅ |

Создайте приложение в [PayPal Developer dashboard](https://developer.paypal.com/dashboard/applications). Test mode использует ваши sandbox-креды.

> ⚠️ **PayPal не умеет списывать KZT.** Валюта магазина должна быть валютой PayPal (USD / EUR / …).
>
> Деньги двигаются **только** когда их списывает Torta. Если клиент подтвердил и бросил оформление — не спишется ничего.

## Manual — наличные / при доставке

Ни кредов, ни API. Включите для наличных, перевода или оплаты при получении. Заказ записывается как **учтённый** (`manual`): деньги вы собираете напрямую и отгружаете. Карта онлайн не списывается.

## Правила валют

Некоторые шлюзы проводят платежи только в одной валюте. Torta **отказывается списать неправильно**, а не угадывает.

| Шлюз | Проводит в |
|---|---|
| ApiPay (Kaspi) | KZT |
| ePay (Halyk) | KZT |
| Robokassa | KZT |
| TipTop Pay | KZT, RUB |
| Stripe | много валют |
| PayPal | много валют, **но не KZT** |

Если клиент выбрал шлюз, который не умеет валюту вашего магазина, оформление тихо **откатывается на Manual**, а не списывает не ту сумму. Если кто-то дёрнет API напрямую с несовместимой парой — заказ будет **отклонён**.

## Какой статус получит заказ

| Ситуация | Статус оплаты |
|---|---|
| Онлайн-шлюз подключён, платёж проверен | **Оплачен** — сразу идёт в выручку |
| Manual | **Учтён** (`manual`) — вы собрали деньги сами |
| Выбран онлайн-метод, но его шлюз не подключён | Записывается как `manual` — продажа не блокируется, но ничего не проверено |
| Старые заказы `other` (до интеграций шлюзов) | **Ожидает оплаты**, пока вы не нажмёте **Mark as paid** в **Orders** |

## Возвраты

Возврат оформляется из **Возврата (Return)**, после того как вы пометили его *inspected*. В магазине с несколькими шлюзами возврат автоматически уходит через **тот шлюз, который принял деньги**.

| Шлюз | Возврат |
|---|---|
| Stripe · ApiPay (Kaspi) · TipTop Pay · Robokassa · PayPal | Через API провайдера, прямо из Torta |
| **ePay (Halyk)** | Пока не подключён — верните деньги в **кабинете Halyk**, затем запишите референс в Torta |
| Manual | Только запись — деньги двигаете сами |

Если API провайдера отклонит возврат, Torta **не** пометит его выполненным. У вас никогда не будет возврата со статусом «возвращено», пока деньги ещё у вас.

## Безопасность в одну строку

Данные карты идут **прямо в платёжную систему** — они не доходят до наших серверов, так что PCI-нагрузка не на вас, а деньги попадают на **ваш** счёт, не на наш. Каждый онлайн-заказ перепроверяется на сервере, прежде чем засчитаться в выручку. Как именно это обеспечено — см. [API: Платежи](/docs/payments-api).
